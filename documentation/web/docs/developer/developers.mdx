# Developers guide

## Development environment prerequisites

* A [dagger](https://dagger.io/) installation

## How to get an ephemeral development environment

For a quick and convenient development experience, you can create an ephemeral
development environment using the `integration:devenv` task from the Taskfile:

```sh
task integration:devenv
```

This command creates and connects you to an ephemeral development environment
with all the necessary components pre-configured, making it easier to test and
develop Klio features without affecting your local setup.

Here are the instructions to deploy the Klio server and the CNPG cluster with
the Klio plugin, using manifests under `operator/config/samples`.
The following commands are executed inside the dagger container created from
the previous step:

```sh
# Deploy the Klio server with the related resources
dagger /apps $ kubectl apply -f ../operator/config/samples/klio_v1alpha1_server.yaml

# Deploy the CNPG Cluster with a patch for the plugin
dagger /apps $ kubectl apply -f ../operator/config/samples/cluster-example.yaml
```

## How to test Klio in a kind cluster during development

During the development phase, it is recommended to test any changes in a test
environment as soon as they are implemented. To perform such a test, a developer
can build and deploy the binaries and the images in a reusable Kubernetes environment.

This section will guide you through the steps required to deploy the Klio operator and
its resources inside a kind cluster.

1. Create a kind cluster using the `hack/setup-cluster.sh` script from the CNPG repository.
2. To build and deploy Klio images and operator, exec the command: `KIND_CLUSTER_NAME=$(kind get clusters) task integration:deploy-to-kind`
3. Once the operator is in `Ready` state, you can deploy the resources:
  * Klio server: `kubectl apply -f operator/config/samples/klio_v1alpha1_server.yaml`
  * CNPG Cluster with Klio plugin: `kubectl apply -f operator/config/samples/cluster-example-plugin.yaml`

Repeat step 2 to deploy the new changes applied to the code, and reset the operator.
Then rollout the new binary in both server and cluster pods:

1. delete the Klio Server pod: `kubectl delete pod server-sample-klio-0`
2. delete the Cluster's pods: `kubectl delete pod -l cnpg.io/cluster=cluster-example`

### How to get performance profiles with pprof

1. Open a port forward connection to port 6061: `kubectl port-forward pod/server-sample-klio-0 6061`
2. run pprof tool, e.g.: `go tool pprof -http=:9999 http://localhost:6061/debug/pprof/profile\?seconds=30`

## How to setup manually a Klio server

Given the following configuration file in `/home/klio/.klio.yaml`:

```yaml
wal:
  listen_address: 0.0.0.0:52000
  tls_cert: /home/klio/server.crt
  tls_key: /home/klio/server.key
  path: /home/klio/klio_data/wals
  encryption_password: cicciopasticcio
  htpasswd_file: /home/klio/klio_data/htpasswd

base:
  repository: /home/klio/klio_data/base
  cache: /home/klio/klio_data/base
  encryption_password: thispassword
  tls_cert: /home/klio/server.crt
  tls_key: /home/klio/server.key
  listen_address: 0.0.0.0:52000
  htpasswd_file: /home/klio/klio_data/htpasswd
  admin_user: kopia
  admin_password: cicciopasticcio
```

A new Klio repository for both WAL and base backups can be bootstrapped with:

```sh
openssl req -x509 -newkey rsa:4096 -sha256 -days 3650 \
  -nodes -keyout server.key -out server.crt -subj "/CN=klio-server" \
  -addext "subjectAltName=DNS:klio-server,IP:127.0.0.1"

~/klio server initialize
```

The Klio WAL server can be started with:

```sh
~/klio server start-wal
```

The Klio base server can be started with:

```sh
~/klio server start-base
```

    slot: klio

## How to setup testing environment on VMs

This section provides instructions to setup a testing environment for Klio using Virtual Machines.

### Requirements

1. SSH access to 3x VMs (Debian)
  * 1x VM for Klio server
  * 1x VM for the original PostgreSQL server
  * 1x VM for the replica PostgreSQL server

2. Download the Klio package from the [latest release](https://github.com/EnterpriseDB/klio/releases/latest)
   or build the Klio binary:

   ```sh
   task core:goreleaser-snapshot
   ```

3. Copy the Klio binary to each server:

   Adjust VM names and user according to your environment.
   ```sh
   vms=("pg-origin" "pg-dest" "klio-server")
   user=root

   for vm in "${vms[@]}"; do scp core/dist/klio_linux_amd64_v1/klio ${user}@${vm}:/tmp; done
   ```

### Setup VM for Klio Server

1. Upgrade and install packages on Klio Server VM:

  ```sh
  # Connect to VM through SSH
  ssh root@klio-server

  # Update packages list and upgrade system
  apt update && apt upgrade -y

  # Install utils
  apt install htop vim curl gpg apache2-utils -y

  # Install Kopia
  curl -s https://kopia.io/signing-key \
    | gpg --dearmor -o /etc/apt/keyrings/kopia-keyring.gpg

  echo "deb [signed-by=/etc/apt/keyrings/kopia-keyring.gpg] http://packages.kopia.io/apt/ stable main" \
    | tee /etc/apt/sources.list.d/kopia.list

  apt update && apt install kopia -y
  ```

2. Setup Klio Server:

  ```sh
  # Create klio user
  useradd -s /bin/bash -m klio

  # Become klio
  su - klio

  # Copy klio binary into klio home
  cp /tmp/klio .

  # Create Klio data directory
  mkdir klio_data

  # Generate server.crt and server.key certificates
  openssl req -x509 -newkey rsa:4096 -sha256 -days 3650 \
    -nodes -keyout server.key -out server.crt -subj "/CN=klio-server" \
    -addext "subjectAltName=DNS:klio-server,IP:127.0.0.1"

  # Create the Klio Server config file in klio home
  cat <<EOF > .klio.yaml
wal:
  listen_address: 0.0.0.0:52000
  tls_cert: /home/klio/server.crt
  tls_key: /home/klio/server.key
  path: /home/klio/klio_data/wals
  encryption_password: cicciopasticcio
  htpasswd_file: /home/klio/klio_data/htpasswd

base:
  repository: /home/klio/klio_data/base
  cache: /home/klio/klio_data/base
  encryption_password: thispassword
  tls_cert: /home/klio/server.crt
  tls_key: /home/klio/server.key
  listen_address: 0.0.0.0:52001
  htpasswd_file: /home/klio/klio_data/htpasswd
  admin_user: kopia
  admin_password: cicciopasticcio
EOF

  # Initialize Klio repository
  ./klio server initialize

  # Create the user:password htpasswd file
  htpasswd -Bbn klio@pg-origin cicciopasticcio | tee klio_data/htpasswd
  ```

3. Start the klio servers on separate terminals:

  ```sh
  # Start kopia server
  ./klio server start-base

  # Start klio server for wal
  ./klio server start-wal
  ```
OR create the systemd services:

  ```sh
  # Create Klio base service for systemd
  cat <<EOF > /etc/systemd/system/klio-base.service
  [Unit]
  Description=Klio Server for Backup Tier-1

  [Service]
  ExecStart=/home/klio/klio server start-base --debug
  User=klio
  Group=klio
  Restart=always

  [Install]
  WantedBy=multi-user.target
EOF

  # Create Klio wal service for systemd
  cat <<EOF > /etc/systemd/system/klio-wal.service
  [Unit]
  Description=Klio Server for WAL Tier-1

  [Service]
  ExecStart=/home/klio/klio server start-wal --debug
  User=klio
  Group=klio
  Restart=always

  [Install]
  WantedBy=multi-user.target
EOF

  # Enable both services
  systemctl daemon-reload
  systemctl enable --now klio-base
  systemctl enable --now klio-wal
  ```

4. Optional: browse kopia server at https://klio-server:52001, login using:

- username: `kopia`
- password: `cicciopasticcio`

### Setup VM for PostgreSQL source server called `pg-origin`

1. Upload the Klio server certificate to the `pg-origin` VM

  ```sh
  scp server.crt root@pg-origin:/tmp/
  ```

2. Setup the PostgreSQL source VM as `root`:

  ```sh
  # Update and install packages
  apt update && apt upgrade -y
  apt install htop vim curl gpg -y

  # Install PostgreSQL
  apt install postgresql-common -y
  /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh -y
  apt update
  apt install postgresql-17 -y
  ```

3. Setup Klio client in PostgreSQL source VM as `root`:

  ```sh
  # Set klio up
  mv /tmp/server.crt /var/lib/postgresql/
  mv /tmp/klio /bin/klio

  # Generate fingerprint and copy it for later
  openssl x509 -in /var/lib/postgresql/server.crt -text -fingerprint -sha256 \
    | grep Fingerprint | awk -F'=' '{print $2}' | tr -d ':'

  # Save the output fingerprint for later
  82205DCAD182AF72534B0735AF13CD24333DE6931C66E156A452F78B745C31BD

  # Create the Klio configuration
  cat <<EOF > /var/lib/postgresql/klio.yaml
client:
  wal:
    server_cert_path: /var/lib/postgresql/server.crt
    address: klio-server:52000
    cluster_name: pg-origin
    username: klio
    password: cicciopasticcio

  base:
    url: https://klio-server:52001
    server_cert_path: /var/lib/postgresql/server.crt
    hostname: pg-origin
    username: klio
    password: cicciopasticcio
    slot: klio
    trusted_server_certificate_fingerprint: 82205DCAD182AF72534B0735AF13CD24333DE6931C66E156A452F78B745C31BD

source:
  dsn: "user=postgres replication=yes"
  standard_dsn: "dbname=postgres"
  slot: klio
EOF

  # Give the right owner to the created file
  chown postgres:postgres /var/lib/postgresql/klio.yaml
  chown postgres:postgres /var/lib/postgresql/server.crt

  # Add klio server in /etc/hosts
  echo "192.168.5.89    klio-server" >> /etc/hosts

  # Create the systemd service for the klio send-wal
  cat <<EOF > /etc/systemd/system/klio-send-wal.service
  [Unit]
  Description=Klio Send WAL

  [Service]
  ExecStart=/bin/klio send-wal --config=/var/lib/postgresql/klio.yaml --debug
  User=postgres
  Group=postgres
  Restart=always

  [Install]
  WantedBy=multi-user.target
EOF

  # Enable the service
  systemctl daemon-reload
  systemctl enable --now klio-send-wal.service
  ```

4. Ensure PostgreSQL and Klio are working correctly

  ```sh
  systemctl status postgresql@17-main.service

  # Send remote command to klio-server through ssh
  ssh root@klio-server "ls /home/klio/klio_data/wals/pg-origin/0000000100000000/*"
  /home/klio/klio_data/wals/pg-origin/0000000100000000/000000010000000000000001
  /home/klio/klio_data/wals/pg-origin/0000000100000000/000000010000000000000002
  /home/klio/klio_data/wals/pg-origin/0000000100000000/000000010000000000000003
  ```

5. Take the first backup as `postgres` user and verify in the klio server

  ```sh
  # Become postgres
  su - postgres

  # Take the backup
  klio backup run --config ./klio.yaml --name mybackup

  # Check backup metadata
  klio backup get-metadata mybackup --config klio.yaml
  ```

6. Optional: browse kopia web and verify the snapshots list: https://klio-server:52001/snapshots.
   In the dropdown menu at the top-left corner, choose `klio@pg-origin` or select `All snapshots`.
